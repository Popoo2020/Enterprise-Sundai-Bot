Scope, responsibilities & boundaries

The fixed package

DevSecOps Foundation: one repository, one pipeline, one deployment target and up to two environments. The entry package covers the stated controls; additional checks and supply-chain features must be explicitly included in the agreement.

Outside this scope

An organisation-wide development-platform migration is excluded. DAST requires a suitable environment; container and IaC checks, SBOM, signing and provenance are included only where agreed. External tooling and licence costs are separately approved.

Your part

Provide authorised repository and deployment access, a technical owner and suitable test environments. Agree release gates, exception handling and rollback approval. Your team owns ongoing pipeline operation after handover.

Illustrative output · not a customer result

Illustrative pipeline, not evidence of a production deployment: commit → code/dependency/secret checks → review gate → short-lived deployment identity → approved release with rollback guidance.

FAQ

Questions, answered.

Will checks block every insecure change?

No. Automated checks have limitations. We agree gate behaviour, severity thresholds and exception ownership; human review and maintenance remain necessary.

Can you add DAST, containers and IaC?

Yes, where the environment and scope support them. DAST needs a suitable test target. Container and infrastructure-as-code checks, SBOM, signatures and provenance are specified in the package agreement.

Does a training certificate prove production delivery?

No. Training, a configured repository and verified production experience are different evidence. Tools are offered only when the assigned practitioner has the relevant capability.
