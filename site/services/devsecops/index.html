Q&A

Good questions. Straight answers.

Will checks block every insecure change?

No. Automated checks have limitations. We agree gate behaviour, severity thresholds and exception ownership; human review and maintenance remain necessary.

Does a training certificate prove production delivery?

No. Training, a configured repository and verified production experience are different evidence. Tools are offered only when the assigned practitioner has the relevant capability.

What is SAST versus SCA?

SAST versus SCA describes different checks: static application security testing examines code patterns; software composition analysis examines third-party dependencies and known issues. They complement secret scanning and human review; none guarantees detection of every problem.

What does the DevSecOps Foundation include?

One repository, one pipeline, one deployment target and up to two environments. The written agreement defines checks, restricted identities, approvals, rollback guidance and acceptance tests. Tool licences and wider migrations are separate.

How do security release gates work?

We agree severity thresholds, what blocks a release and who can approve exceptions. Security gate exception handling records the reason and owner. A passing automated check does not replace review of the actual change.

Can we add DAST or container checks?

DAST integration needs a suitable test environment. Container image security scanning and infrastructure-as-code security checks are included only when explicitly agreed and supported by the target environment.

Can you add SBOM, signing and provenance?

Software bill of materials setup records software components. Build signing and provenance provide agreed evidence about artefacts and their origin. These are separately specified supply-chain controls, rather than automatic features of the entry package.

What happens after handover?

Your team owns ongoing operation and maintenance. We hand over the configured checks, deployment approval workflow and secure deployment rollback plan, with agreed acceptance evidence. Further support needs its own scope.
