Værdien, uden omsvøb

En vurdering af cloudsikkerhed begynder med, hvem der kan gøre hvad, og om teamet kan se det. En gennemgang af cloud-IAM og en gennemgang af privilegeret adgang gør uklare rettigheder lettere at håndtere. Vi vælger én udbyder, aftaler ændringer og overdrager en behandlingsplan.

Fra første spørgsmål til en brugbar overdragelse

  1. 01

    Vælg konto og relevante identiteter

    Vælg rådgivning om Azure-sikkerhed, rådgivning om AWS-sikkerhed eller rådgivning om Google Cloud-sikkerhed for ét abonnement, én konto eller ét projekt. Grundlaget omfatter op til ti identiteter og ti valgte ressourcer.

  2. 02

    Gennemgå rettigheder og signaler

    Aftal udbyderens adgangskontroller, en baseline for cloud-MFA, opsætning af revisionslogs i cloud og op til fem regler for cloudsikkerhedsalarmer. Licenser og tilladte ændringer afklares før implementering.

  3. 03

    Overdrag et grundlag, der kan drives

    Ændringer testes og godkendes før aktivering. En procedure for nødadgang til cloud og en gennemgang af cloud-backup og gendannelse adresserer aftalte spørgsmål om recovery med ansvar og dokumentation.

Q&A

Gode spørgsmål. Klare svar.

Hvilke identitetskontroller er relevante?

Azure: Azure RBAC, Microsoft Entra ID, Conditional Access og Entra PIM. AWS: IAM policies og roles, IAM Identity Center, STS og rettighedsgrænser efter behov. Google Cloud: Cloud IAM roles og policy bindings, IAM Conditions og Privileged Access Manager. Kontrollerne afhænger af leverandør og licenser. PIM/PAM styrer privilegeret adgang og er ikke andre navne for RBAC.

Hvad omfatter månedlig Cloud Security Care?

En særskilt aftalt månedsydelse omfatter planlagte rettigheds- og konfigurationskontroller, alarmgennemgang, mindre ændringer og en rapport: op til seks arbejdstimer om måneden efter en aftalt backlog. Ekstra timer kræver en godkendt udvidelse og faktureres ikke automatisk.

Kan I hjælpe ved en sikkerhedshændelse?

Indledende håndtering, indsamling af evidens og overdragelse til en specialist kan aftales efter tilgængelighed. Akut dækning og responstider kræver passende bemanding, vagtordning og SLA og indgår ikke automatisk.

Hvilke Azure-kontroller kan I gennemgå?

En sikkerhedsgennemgang af Microsoft Entra ID og en gennemgang af Azure RBAC-rettigheder kan undersøge aftalte identiteter og ressourcer. En baseline for Conditional Access eller en gennemgang af Microsoft Entra PIM-konfiguration afhænger af licenser, tilladelser og omfang.

Hvilke AWS-kontroller kan I gennemgå?

En gennemgang af AWS IAM-politikker undersøger aftalte politikker og roller. En gennemgang af AWS IAM Identity Center kan undersøge medarbejderadgang i omfanget. STS og rettighedsgrænser overvejes, hvor relevant; teamet godkender ændringer før aktivering.

Hvilke Google Cloud-kontroller kan I gennemgå?

En gennemgang af Google Cloud IAM-politikker kan undersøge valgte roller, bindinger og betingelser. En gennemgang af Google Cloud Privileged Access Manager omfatter aftalte privilegiekontroller. PIM og PAM er tjenester til privilegeret adgang, ikke andre navne for RBAC.

Hvad omfatter månedlig vedligeholdelse af cloudsikkerhed?

Månedlig vedligeholdelse af cloudsikkerhed er en særskilt aftalt ydelse: planlagte rettigheds- og konfigurationstjek, alarmgennemgang, små ændringer og en rapport inden for op til seks arbejdstimer om måneden på en aftalt backlog. Ekstra arbejde kræver godkendt udvidelse.

Omfatter pakken akut hændelseshåndtering?

Ingen automatisk vagtordning eller 24/7 SOC indgår. Indledende evidensindsamling eller specialistoverdragelse kan aftales afhængigt af kapacitet. En svartidsgaranti kræver bemanding, en særskilt vagtaftale og en SLA.

Hvilken adgang og hvilke beslutninger skal I bruge?

Stil autoriseret adgang, korrekt aktivoversigt, teknisk ejer og ændringsgodkender til rådighed. Aftal licenser, nødkontakter og recoverykrav. Vi afgrænser gennemgang af cloud-IAM og acceptkriterier før opgavestart.
